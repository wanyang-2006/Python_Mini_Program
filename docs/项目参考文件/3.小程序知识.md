### 主流的小程序开发模式

小程序开发‌‌‌主要分两大流派，理解它们的区别，有助于看懂؜后面方؜案设计؜为⁠什么要纠⁠结技术选⁠型：Dox2/+YoJVhv3Q4JA7Buu/g9gI6L6PQLw5wjMgFYJew=

- 原生开发：直接用微信官方的 WXML / WXSS / JS 写。官方能力最全、最稳，但只能做微信单端，想扩展到 H5 / App 很麻烦。
- 跨端框架开发：用 Taro、uni-app 这类框架，写一套代码编译到多个平台（小程序 / H5 / App）。开发效率高、能多端复用，代价是要处理一些跨端兼容问题。

本项目最终选了跨端‌‌‌框架 Taro，既能快速做出微信小程序，又给后续扩展到其他平台留了余地。具体的选型对比，会在下一期方案设计里؜؜؜详细展开              ⁠⁠⁠                  

### 「先做出来，再系统学」的学习心态

强调一个学习思路： **先用 AI 编程快速做出一个能跑的小程序，再回头按路线系统学习。**

这对新手非‌常重要‌‌。传统学法是「先啃完所有基础再动手」，很容易学到一半؜就放弃               ؜؜                ⁠⁠ 而 A⁠I 编程时代更推荐的是：

```
用 AI 快速做出 MVP → 在实践中遇到具体问题 → 带着问题去系统学 → 理解更深、更有动力
```

先有成就感和完‌整体‌验，再‌补理论，是这套教程一以贯之的方法论。所以这一节看不懂底层原理完全没关؜系，跟着做、多实践，理解会⁠随着项目推进؜自然加深                ⁠؜                           ⁠
