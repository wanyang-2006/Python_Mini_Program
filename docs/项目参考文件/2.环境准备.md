#### Node.js 到底是干嘛的？

很多新手对「为什么做小程序还要装 Node」感到困惑。其实 Node.js 在这个项目里不是用来写业务代码的，而是作为各种工具的「运行底座」：

- 小程序前端用的 Taro 框架，依赖 Node 来安装依赖、编译打包
- MCP 服务很多是通过 `npx` 启动的，而 `npx` 随 Node 一起安装
- Agent Skills 的安装命令也基于 Node 生态

可以简单理解为： **Node.js 是前端和工具链的「水电煤」，先把它装好，后面的工具才能正常跑起来。** 装完后用 `node -v` 和 `npm -v` 两条命令验证，能输出版本号就 OK。

### 2、AI 编程扩展 - MCP

MCP 的全称是 Model Context Protocol 模型上下文协议。简单来说，就是让 AI 大模型能够连接外部工具和数据源的一个开放标准。

打个比方，MCP 就像是 AI 的 USB-C 接口，原本 AI 只能根据训练数据来回答问题、生成代码，但有了这个统一接口，它就能连接各种外部工具，比如打开浏览器看网站、搜索并抓取网页内容、部署项目到云端、访问数据库等等，能力一下子就丰富起来了。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/oaSlJtBZJ4HMWNlW.webp)

下面我们来安装几个项目中可能会用到的 MCP。

#### 这个项目为什么要装这几个 MCP？

MCP 不是装得越多越好，而是根据项目需要来装。本项目要装的三个 MCP，正好对应三类高频需求：

 =

| MCP | 解决什么问题 | 在本项目的用途Dox2/+ |
| --- | --- | --- |
| Firecrawl | 让 AI 能抓取和理解网页内容 | 竞品调研、读官方文档、抓取参考资料 |
| Context7 | 让 AI 获取最新的技术文档 | 避免用过时的 Taro / LangChain 写法 |

理解了「每个 MCP 解决一类问题」之后，以后做新项目你就能按需选择，而不是盲目跟着装。

#### Firecrawl MCP 网页内容抓取

首先要介绍的是 [Firecrawl MCP](https://www.firecrawl.dev/) ，让 AI 能够自动抓取和理解网页内容。

我在开发项目时经常需要从网上获取参考资料、阅读官方文档和技术博客，或者分析竞品的功能实现。如果人工来做这件事，需要先打开网站、再手动复制粘贴内容，或者自己写个爬虫脚本，麻烦得一批。

有了 Firecrawl MCP，这事儿就简单多了。我直接在 AI 编程工具中跟 AI 说：

- 帮我获取这个网站的内容
- 帮我读一下这个文档
- 帮我从网上搜索 XX 相关的信息

它就能自动把网页的内容、结构、甚至是动态加载的数据都给我抓下来。

#### API Key 是什么？为什么大多数 MCP 都要它？

你会发现，几乎每个 MCP（Firecrawl、Context7、后面的 Tavily 等）都要先注册账号、拿一个 API Key 再填进去。API Key 可以理解为「访问某个云服务的身份令牌」：

- 它代表「你」这个用户去调用对方的服务
- 服务商用它来识别身份、统计用量、控制免费额度
- 所以 API Key 等同于密码，绝对不能泄露、不能提交到 GitHub

后面项目里会反复出现「获取 API Key → 填到配置里」这个动作，理解了这一层，再遇到新的服务就不会懵了。

#### Context7 获取最新文档

[Context7](https://context7.com/) 能帮 AI 获取到最新的技术文档。

我们都知道，AI 的训练数据是有截止时间的，比如 GPT-4 的知识可能只更新到 2023 年。这就导致一个问题，当你问 AI 关于某个框架最新版本的用法时，它给出的答案可能是过时的。

Context7 就是来解决这个问题的。它会自动从官方文档网站抓取最新的、特定版本的文档内容，然后提供给 AI。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/14VJH1e8jfvP3AyC.webp)

这样一来，AI 给出的代码示例和建议就是基于最新文档的，不会去用已经废弃的写法，大大提高了项目能正常运行的概率。

**如何使用？**

访问 [Context7 Dashboard](https://context7.com/dashboard) 注册账号并获取 API Key，个人使用是免费的。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/AcSLU1ThqZO0D2V8.webp)

在 Copilot 中安装 Context7，和之前的操作一样：

![](https://pic.code-nav.cn/course_picture/1608440217629360130/OhmTTRth47faOTf5.webp)

进入配置并填写 API Key：

![](https://pic.code-nav.cn/course_picture/1608440217629360130/CmxxfWVecEMOdROV.webp)

之后你在 AI 编程工具中跟 AI 对话时，只要跟技术文档相关，或者主动提一嘴 “use context7”，它就会自动去获取最新文档来回复你。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/BJZhRAE0HNQcY96x.webp)

#### 为什么 Context7 对这个项目特别重要？

本项目用到的 Taro、LangChain 这类框架，更新迭代非常快，AI 凭训练记忆写出来的代码很可能是旧版本的，一跑就报错。Context7 的价值就在于：

```
AI 要写 Taro 代码 → 先用 Context7 拉取 Taro 最新文档 → 基于最新 API 生成代码 → 代码能正常跑
```

所以后面开发环节的提示词里，会反复要求 AI「必须通过 Context7 或官方文档获取最新用法」，本质上就是在用这个 MCP 给 AI 的代码质量上保险。

#### Playwright 浏览器自动化

Playwright MCP Server 是一个用于浏览器自动化的服务工具，它的作用是让 AI 能直接控制真实浏览器完成网页操作。它不依赖用户手动点击或截图，而是通过代码驱动浏览器加载页面、执行交互、提取内容

![](https://pic.code-nav.cn/course_picture/1608440217629360130/1rbAmHAmHIEKCRTP.webp)

安装之后，AI 就能自动操作浏览器了，比如让它网页截图：

![](https://pic.code-nav.cn/course_picture/1608440217629360130/TyE64mOfNMfWM4aw.webp)

#### Playwright 让 AI 实现「自己测自己」

Playwright 最大的价值，是让 AI 具备了「闭环验证」的能力。没有它的时候，AI 写完前端代码，得靠你手动打开页面、截图、再把问题描述给它；有了它，AI 可以：

- 自己打开页面看效果
- 自己截图判断 UI 对不对
- 发现问题自己改、改完再验证

这正是后面开发环节提到的「让 AI 用 Browser Use 自行测试验证」的底层能力，能大幅减少人工来回沟通的成本。

### 3、AI 编程扩展 - Agent Skills

可以看这个教程快速入门 Skills： [https://ai.codefather.](https://ai.codefather.)

[Agent Skills](https://claude.com/blog/skills) 是 Anthropic 推出的 [一套开放标准](https://platform.claude.com/docs/zh-CN/agents-and-tools/agent-skills/overview) ，目的是让 AI 能够学习使用各种专业技能，而不用每次都重复输入提示词。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/mo8gdWh4NkQtyTUf.webp)

它定义了一种 **封装 AI 工作流** 的标准：开发者可以把复杂的任务指令、脚本和资源打包成一个 **技能（Skill）** ；作为用户，你只需要安装这些技能，AI 就能立刻学会这项本事，不用重复造轮子。

简单来说，它就是给 AI 装备的 **技能包** 。技能包里有精心设计的提示词、代码脚本、还有各种资源文件。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/RyP13LdwkstRffsO.webp)

把 AI 想象成一个职场小白，给他装上 `文档处理技能` ，它就立刻知道怎么生成 PPT、处理 Excel 表格；装上 `代码规范技能` ，它就知道怎么按照公司标准写代码。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/Qmze7DFiNbWKCIFg.webp)

#### 和 MCP 的区别？

**MCP 就像给 AI 装上了 “手和眼睛”** ，让 AI 能够连接外部工具和数据源，比如搜索网页、读取代码仓库、查询数据库。适合需要获取数据或操作外部系统的场景。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/QvfMXWQnEtR9kq4j.webp)

**而 Agent Skills 更像是给 AI 发了一本 “工作手册”** ，把专业知识和工作流程打包起来，教 AI 在特定领域该怎么做。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/sYNCzPs2jUE0l043.webp)

其实 MCP 和 Skills 是可以结合起来的。举个例子，如果你想让 AI 帮你发周报：

- MCP 负责获取数据：从任务管理数据库拉取这周的任务列表
- Skills 负责加工数据：把获取到的原始数据整理成老板爱看的格式

一个提供食材，一个提供配方。

![](https://pic.code-nav.cn/course_picture/1608440217629360130/u4ItM6MPJFaW5hQP.webp)

#### MCP 和 Skills 的区别

这俩概念新手最容易搞混，用一个表格彻底分清：

 =

| 对比项 | MCP | Agent |
| --- | --- | --- |
| 本质 | 连接外部工具的「接口/协议」 | 封装工作流的「知识包/手册」 |
| 比喻 | AI 的「手和眼睛」 | AI 的「工作手册」 |
| 解决 | 能不能拿到数据、能不能操作系统 | 会不会按规范把事做漂亮 |
| 举例 | Firecrawl 抓网页、查数据库 | frontend-design 美化页面 |

记住一句话就够了： **MCP 管「能不能做到」，Skills 管「做得好不好」，两者还能配合，一个提供食材，一个提供配方。**

#### 技能的两种触发方式

安装完技能后，怎么让 AI 用上它？有两种方式：

- 自动触发：AI 根据你描述的任务，自己判断该不该用某个技能（比如你说「帮我美化页面」，它会自动想到 frontend-design）
- 手动触发：用斜杠命令显式指定，比如 `/frontend-design 帮我启动开发` ，强制让 AI 走这个技能

> 💡 实践经验：自动触发有时候不够稳，AI 可能「忘了」用技能。所以在关键步骤，推荐用斜杠命令手动触发，确保技能一定被调用。后面 UI 开发环节就会大量用到 `/frontend-design` 、 `/ui-ux-pro-max` 这样的手动触发。
