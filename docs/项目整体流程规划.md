# 项目整体流程规划 — Python 全栈 AI 答题小程序

> 版本：v1.0 | 日期：2026-11-12 | 状态：已确认

## 一、技术栈决策（已确认）

| 维度 | 选型 | 说明 |
|------|------|------|
| 前端框架 | Taro 4.x + React 18 + TypeScript | 跨端、AI 友好、纯命令行操作 |
| 状态管理 | Zustand | 轻量，适合小程序规模 |
| 后端框架 | Python 3.11+ + FastAPI | 异步高性能，自动生成 API 文档 |
| AI 链路 | LangChain + DeepSeek (deepseek-chat) | with_structured_output 约束 JSON 输出 |
| 数据库 | MySQL 8.x（全程使用） | 关系数据，长期演进，全阶段统一使用 |
| ORM | SQLAlchemy 2.x + Alembic | 迁移管理，版本化变更 |
| 鉴权 | 微信静默登录 + JWT | 用户无感，安全可靠，Phase 6 引入 |
| UI 风格 | 简约现代教育风 | 蓝绿主色（`#4A9EDE` / `#5BC8AF`），白底，圆角卡片 |
| 敏感配置 | `.env` 文件（加入 .gitignore） | DeepSeek Key / MySQL DSN / 微信密钥 |

## 二、项目目录结构（目标态）

```
├── miniprogram/        # Taro 前端项目
│   └── src/
│       ├── pages/      # index / quiz / report / history / profile
│       ├── components/ # 题卡、进度条、报告卡等公共组件
│       └── store/      # Zustand 状态管理
├── backend/            # FastAPI 后端
│   ├── app/
│   │   ├── api/        # 路由：quiz.py / user.py
│   │   ├── models/     # SQLAlchemy 数据模型
│   │   ├── schemas/    # Pydantic 请求/响应模型
│   │   └── services/   # LangChain 出题/报告服务
│   ├── alembic/        # 数据库迁移文件
│   └── .env            # 敏感配置（不提交 Git）
└── docs/
    ├── 项目参考文件/   # 原始教程文档（只读参考）
    ├── prototype/      # HTML 版原型（Phase 4A 产出）
    ├── 项目整体流程规划.md  # 本文件
    └── 需求规格说明.md      # Phase 1 产出
```

### Phase 4：UI 原型开发

分两个子阶段：先 HTML 静态原型确认视觉，再迁移到 Taro。

#### Phase 4A：HTML 版原型

**目标**：用纯 HTML/CSS 快速产出可在浏览器直接打开的视觉原型，确认 UI 方向再写小程序代码。

视觉基调：主色 `#4A9EDE`（蓝）+ `#5BC8AF`（绿），白底，圆角卡片，无多余装饰。

| # | 页面文件 | 核心 UI 元素 |
|---|---------|------------|
| 4A.1 | `docs/prototype/index.html` | Logo、主题输入框、"开始闯关"按钮、历史入口 |
| 4A.2 | `docs/prototype/quiz.html` | 进度条(1/5)、题目卡片、4 个选项按钮、答后反馈区（讲解）|
| 4A.3 | `docs/prototype/report.html` | 得分展示、题目复盘列表、AI 总结文本、重新开始按钮 |
| 4A.4 | `docs/prototype/history.html` | 历史会话卡片列表（主题/日期/得分/正确率）|

**产出物**：4 个独立 HTML 文件（含内联 CSS），可直接在浏览器打开查看

#### Phase 4B：Taro 框架搭建

**目标**：脚手架初始化项目，搭建页面骨架，将 HTML 原型视觉迁移为 Taro 组件。

| # | 任务 | 命令 / 说明 |
|---|------|-----------|
| 4B.1 | 初始化 Taro 项目 | `taro init miniprogram`（React + TypeScript 模板）|
| 4B.2 | 配置基础依赖 | 添加 Zustand，配置 `app.config.ts` tabBar（首页/历史）|
| 4B.3 | 创建 4 个页面骨架 | pages/index / quiz / report / history |
| 4B.4 | 建立设计 Token | CSS Variables：颜色/字号/间距（从 HTML 原型提取）|
| 4B.5 | 迁移 HTML → Taro JSX | 参照 HTML 原型重写页面布局（静态数据占位）|
| 4B.6 | 微信开发者工具预览 | 验证页面可正常编译渲染（无接口调用，静态展示）|

> ⚠️ **用户操作点**：用微信开发者工具打开 `miniprogram/dist`，填写 AppID（测试号即可）

**产出物**：`miniprogram/` 完整初始化项目，4 个页面可在开发者工具中静态预览

### Phase 5：核心功能开发（MVP）

**开发顺序**：后端出题接口 → 前端闯关页联调 → 后端报告接口 → 首页闭环 → 本地历史记录

#### Phase 5A：后端基础与出题接口

| # | 任务 |
|---|------|
| 5A.1 | FastAPI 项目初始化（`backend/` 目录结构，`requirements.txt`，虚拟环境）|
| 5A.2 | SQLAlchemy 连接 MySQL，Alembic 建 quiz_sessions / questions / reports 表 |
| 5A.3 | LangChain 出题 Chain（`with_structured_output()` + Pydantic 模型约束 JSON）|
| 5A.4 | 实现 `POST /api/quiz/generate`，题目存入 MySQL，返回 session_id |
| 5A.5 | 本地 curl 测试：验证出题接口正常返回 5 道结构化题目 |

> ⚠️ **注意**：DeepSeek 不支持 `response_format` 参数，改用 LangChain `with_structured_output()`

#### Phase 5B：前端闯关页联调

| # | 任务 |
|---|------|
| 5B.1 | 首页输入主题 → 调用 `/api/quiz/generate` → `Taro.navigateTo` 跳转闯关页 |
| 5B.2 | 闯关页渲染题目与选项（Zustand 存储当前 session_id 和题目列表）|
| 5B.3 | 点击答案 → 调用 `/api/quiz/answer` → 展示讲解反馈，解锁"下一题"按钮 |
| 5B.4 | 5 题结束后跳转报告页（报告页不在 tabBar，用 `Taro.navigateTo`）|

#### Phase 5C：报告与完整闭环

| # | 任务 |
|---|------|
| 5C.1 | 实现 `POST /api/quiz/report`（DeepSeek 生成个性化总结，存 reports 表）|
| 5C.2 | 报告页渲染：得分展示、题目复盘、AI 总结 |
| 5C.3 | 本地历史记录（`wx.setStorageSync` 存会话摘要：主题/时间/得分）|
| 5C.4 | 历史页读取本地存储，展示历史会话卡片列表 |
| 5C.5 | 端到端测试：首页→出题→答题→报告→历史，完整流程跑通 |

**产出物**：后端 3 个接口可用 + 前端 4 页联调 + MVP 流程端到端可用

### Phase 6：用户系统开发

**目标**：引入微信身份，将历史记录从本地迁移到服务端，支持多设备查看。

> ⚠️ **Phase 6 开始前用户必须手动完成**：
> 1. 在微信公众平台注册小程序，获取正式 AppID + AppSecret
> 2. 将 AppID + AppSecret 填入 `backend/.env`
> 3. 微信开发者工具"设置 → 项目设置"勾选"不校验合法域名"

| # | 任务 | 说明 |
|---|------|------|
| 6.1 | 前端微信静默登录 | `wx.login()` 获取临时 code，发给后端 |
| 6.2 | 后端 code2session | 用 AppID+AppSecret 换取用户 open_id |
| 6.3 | 建 users 表 | user_id, open_id, nickname, avatar, created_at |
| 6.4 | quiz_sessions 加 user_id FK | Alembic 新增迁移，历史会话与用户绑定 |
| 6.5 | JWT 签发与验证 | 登录后返回 JWT，后续接口用 Bearer Token 鉴权 |
| 6.6 | 实现 `GET /api/user/history` | 服务端历史记录（按 user_id 过滤）|
| 6.7 | 前端个人中心页 | 头像/昵称展示，登录状态管理（Zustand）|
| 6.8 | 历史页切换到服务端数据 | 替代 Phase 5C 的本地存储 |
| 6.9 | tabBar 新增"我的"入口 | pages/profile 加入 tabBar 配置 |

> ⚠️ **关键约束**：只扩展功能，不改动现有出题/答题/报告核心流程（Phase 5 代码不动）

**产出物**：完整用户系统 + 服务端历史记录 + 个人中心页 + 更新 tabBar

## 五、已知风险与应对

| 风险 | 应对措施 |
|------|---------|
| DeepSeek 不支持 `response_format` | 改用 LangChain `with_structured_output()` + Pydantic 模型 |
| `Taro.redirectTo` 无法跳 tabBar 页 | 改用 `Taro.switchTab` |
| MySQL 本地安装配置复杂 | 提供 Docker Compose 一键启动方案 |
| `.env` 文件误提交 Git | 生成时立即加入 `.gitignore` |
| DeepSeek 响应慢/超时 | 前端加 loading 状态，后端设置合理超时 |
| 微信 AppID 获取需手动操作 | Phase 6 前提前告知用户，测试号即可 |
