## 一、技术架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  前端（微信小程序）                                           │
│  Taro 4.x + React 18 + TypeScript + Zustand                  │
│  页面：首页 / 闯关答题 / 结果报告 / 历史记录 / 个人中心(P6)   │
└───────────────────┬─────────────────────────────────────────┘
                    │ HTTP / JSON
┌───────────────────▼─────────────────────────────────────────┐
│  后端（FastAPI 路由层）                                       │
│  参数校验（Pydantic v2）→ 路由分发 → 统一响应格式封装         │
├─────────────────────────────────────────────────────────────┤
│  Service 层                                                   │
│  LangChain ChatOpenAI(DeepSeek) + with_structured_output()   │
│  出题 Chain / 答题判定 / 报告生成 Chain                       │
├─────────────────────────────────────────────────────────────┤
│  数据层                                                       │
│  SQLAlchemy 2.x ORM + Alembic 迁移                           │
│  MySQL 8.x（quiz_sessions / questions / reports / users）     │
└─────────────────────────────────────────────────────────────┘
```

**模块职责**

| 层 | 职责 | 关键约束 |
|----|------|----------|
| API 层（`app/api/`） | 参数校验、路由、统一响应包装 | 只做 I/O 转换，不含业务逻辑 |
| Service 层（`app/services/`） | LangChain 调用、业务规则、答题判定 | 所有 DeepSeek 调用走此层 |
| Models 层（`app/models/`） | SQLAlchemy ORM 定义 | 只建表/建关系，不含业务逻辑 |
| Schemas 层（`app/schemas/`） | Pydantic 请求/响应/结构化输出模型 | 与 ORM 解耦 |

## 二、MVP 5 功能详细设计

### 功能 1：用户输入知识主题

**用户流程**

```
打开小程序首页
  → 看到输入框（提示文字："输入你想学的知识，如 Python 基础、历史朝代..."）
  → 输入 1-100 字的学习主题
  → 点击"开始闯关"按钮
  → 前端显示 loading（DeepSeek 生成中，约 3-8 秒）
  → 生成成功后跳转闯关答题页
  → 若生成失败（网络/AI 超时）显示错误提示，停在首页可重试
```

**前端（首页 `/pages/index/index`）状态**

| 状态 | UI 表现 |
|------|---------|
| idle | 输入框 + "开始闯关"按钮（蓝绿主色） |
| loading | 按钮变灰，loading 旋转动画，文字"AI 生成题目中..." |
| error | toast 提示错误原因，恢复 idle 状态 |

**后端校验规则**

- `topic` 不能为空，不能超过 100 字
- 不限制语言（中英文均可）
- 不过滤话题敏感性（MVP 阶段）

### 功能 2：AI 自动生成交互式闯关题目

**生成规格（固定）**

| 项目 | 规格 |
|------|------|
| 题目总数 | 5 题 |
| 题型组合 | 单选题 3 题 + 多选题 1 题 + 判断题 1 题 |
| 单选题选项 | 4 个（A/B/C/D） |
| 多选题选项 | 4 个（A/B/C/D），答案 2-3 个 |
| 判断题选项 | 2 个（["对", "错"]） |
| 难度分布 | 2 easy + 2 medium + 1 hard，由易到难 |
| 知识点标签 | 每题 1-3 个 |
| 讲解 | 每题 3-5 句，讲清为什么是这个答案 |

**生成流程**

```
接收 topic
  → quiz_service.generate_quiz(topic)
      → 构造 SystemMessage + HumanMessage（含 topic）
      → chain = llm.with_structured_output(QuizSet)
      → quiz_set = chain.invoke(messages)
      → 写 quiz_sessions（status='in_progress'）
      → 批量写 questions（不含 user_answer/is_correct）
      → 返回 session_id + 题目列表（隐去 correct_answer/explanation）
```

**关键约束**

- DeepSeek 不支持 `response_format` 参数，必须用 `llm.with_structured_output(QuizSet)`
- 返回给前端的题目列表**不含** `correct_answer` 和 `explanation`，防止作弊
- 生成超时设置 60 秒（DeepSeek 偶发慢响应）

**出题 LangChain Prompt**

SystemMessage：
```
你是一名专业的 AI 学习教练，擅长根据任意学习主题生成交互式闯关题目。
你需要生成 5 道题目，题型组合为：前 3 道单选题、第 4 道多选题、第 5 道判断题。
每道题必须包含：题号(question_no)、题型(question_type)、题干(content)、
选项列表(options)、正确答案(correct_answer)、讲解(explanation)、
知识点标签(knowledge_tags)、难度(difficulty)。
题目难度由易到难递进（2 easy, 2 medium, 1 hard），覆盖基础概念到实际应用。
讲解需简明扼要，3-5 句话讲清为什么是这个答案，帮助学习者理解记忆。
输出必须严格符合结构化输出 schema，不要输出 schema 之外的任何内容。
```

HumanMessage（`{topic}` 为变量占位）：
```
请围绕以下学习主题生成 5 道闯关题目：
学习主题：{topic}

约束要求：
1. 题目内容必须与主题强相关，不偏题，不出与主题无关的通识题
2. 单选题（question_type="single"）：4 个选项 ["A. ...", "B. ...", "C. ...", "D. ..."]，correct_answer 为 "A"/"B"/"C"/"D" 之一
3. 多选题（question_type="multiple"）：4 个选项，correct_answer 为多个字母，如 "A,C" 或 "A,B,D"
4. 判断题（question_type="judge"）：选项固定为 ["对", "错"]，correct_answer 为 "对" 或 "错"
5. 难度：第1-2题 easy，第3-4题 medium，第5题 hard
6. knowledge_tags 为 1-3 个简短标签，如 ["变量", "数据类型"]
```

**Pydantic 结构化输出模型（schemas/quiz.py 参考）**

```python
from pydantic import BaseModel
from typing import Literal

class QuestionItem(BaseModel):
    question_no: int                                 # 1-5
    question_type: Literal["single", "multiple", "judge"]
    content: str                                     # 题干
    options: list[str]                               # 选项列表
    correct_answer: str                              # "A" / "A,C" / "对"
    explanation: str                                 # 讲解
    knowledge_tags: list[str]                        # 知识点标签
    difficulty: Literal["easy", "medium", "hard"]

class QuizSet(BaseModel):
    questions: list[QuestionItem]                    # 固定 5 题
```

### 功能 3：用户逐题作答，立即显示正误和知识讲解

**用户流程**

```
进入闯关答题页（携带 session_id + 5 题数据）
  → 显示第 1 题（题号/总数进度条 + 题干 + 选项按钮）
  → 用户点击选项（单选直接提交，多选点击多个后点"提交"，判断点击后提交）
  → 前端 loading（后端判定中）
  → 收到结果：
    - 正确：✅ 绿色高亮正确选项 + 显示讲解 + 知识点标签
    - 错误：❌ 红色高亮错误选项 + 绿色高亮正确选项 + 显示讲解
  → 显示"下一题"按钮
  → 第 5 题答完后按钮变为"查看报告"
  → 点击"查看报告"→ 调 report 接口 → 跳转报告页
```

**前端答题页状态机**

```
answering → submitting → result_shown → (next question | report)
```

**后端判定逻辑**

- `single`：`user_answer.upper() == correct_answer.upper()`
- `multiple`：排序后对比，`set(user_answer.split(",")) == set(correct_answer.split(","))`
- `judge`：`user_answer == correct_answer`（"对"/"错"严格匹配）
- 判定后更新数据库：`questions.user_answer`、`questions.is_correct`
- 更新会话：`quiz_sessions.correct_count += 1`（若答对）

**接口：POST /api/quiz/answer**

请求：
```json
{
  "session_id": 1,
  "question_no": 1,
  "user_answer": "A"
}
```

响应：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "question_no": 1,
    "is_correct": true,
    "correct_answer": "A",
    "explanation": "变量是存储数据的容器，Python 中使用赋值符号 = 创建变量...",
    "knowledge_tags": ["变量", "赋值"],
    "current_correct_count": 1
  }
}
```

**错误情况处理**

| 错误 | HTTP 状态 | code | message |
|------|-----------|------|---------|
| session 不存在 | 404 | 1001 | 会话不存在 |
| 题目已作答 | 400 | 1002 | 该题已作答，不可重复提交 |
| question_no 超出范围 | 400 | 1003 | 题号无效 |
| 答案格式错误 | 400 | 1004 | 答案格式不正确 |

### 功能 4：通关后生成知识总结与复盘报告

**触发时机**：5 题全部作答完毕，前端调用 `POST /api/quiz/report`

**报告内容规格**

| 字段 | 说明 |
|------|------|
| 正确率 | `correct_count / total_questions * 100`，保留 1 位小数 |
| 评价话术 | ≥80%："太棒了！掌握情况优秀" / 60-79%："不错，继续努力" / <60%："还需加强，多练习" |
| 知识总结 | AI 生成，200 字内，概括本次学习的核心知识点 |
| 薄弱知识点 | AI 识别错题对应的知识点，数组形式，0-3 个 |
| 答题明细 | 每题的题干、用户答案、正确答案、是否答对 |

**生成流程**

```
接收 session_id
  → 校验 session 下 5 题全部已答（is_correct 非 NULL）
  → 统计 correct_count / accuracy_rate
  → 整理错题摘要（wrong_questions_summary）
  → report_service.generate_report(topic, accuracy, wrong_summary)
      → 构造 SystemMessage + HumanMessage
      → chain = llm.with_structured_output(ReportOutput)
      → report = chain.invoke(messages)
  → 写 reports 表
  → 更新 quiz_sessions.status = 'completed'
  → 返回完整报告
```

**报告 LangChain Prompt**

SystemMessage：
```
你是一名学习复盘教练，根据用户的答题情况生成知识总结与复盘报告。
你需要输出：知识总结（summary）、薄弱知识点列表（weak_points）、评价话术（evaluation）。
评价话术规则：正确率 >= 80 输出"太棒了！掌握情况优秀"，60-79 输出"不错，继续努力"，< 60 输出"还需加强，多练习"。
知识总结：200 字以内，以积极鼓励的语气概括本次学习的核心知识点，不要重复评价话术。
薄弱知识点：从错题的 knowledge_tags 中提取，去重后返回数组，若全对则返回空数组 []。
输出必须严格符合结构化输出 schema。
```

HumanMessage（`{topic}` `{accuracy}` `{wrong_questions_summary}` 为变量占位）：
```
学习主题：{topic}
答题正确率：{accuracy}%
错题情况摘要：
{wrong_questions_summary}

请生成复盘报告。
```

`wrong_questions_summary` 的格式（由 Service 层构造，非 AI 生成）：
```
第2题（多选）：用户答 A,B，正确答案 A,C，知识点：[列表推导式, 循环]
第4题（判断）：用户答 错，正确答案 对，知识点：[函数作用域]
```
（若全对则传 "全部回答正确，无错题"）

**Pydantic 结构化输出模型**

```python
class ReportOutput(BaseModel):
    summary: str           # 知识总结，200 字内
    weak_points: list[str] # 薄弱知识点，可为空列表
    evaluation: str        # 评价话术
```

**接口：POST /api/quiz/report**

请求：
```json
{ "session_id": 1 }
```

响应：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "session_id": 1,
    "topic": "Python 基础语法",
    "accuracy_rate": 80.0,
    "correct_count": 4,
    "total_questions": 5,
    "evaluation": "不错，继续努力",
    "summary": "本次学习涵盖了 Python 变量赋值、数据类型、列表操作等核心概念...",
    "weak_points": ["列表推导式", "函数作用域"],
    "question_details": [
      {
        "question_no": 1,
        "content": "...",
        "user_answer": "A",
        "correct_answer": "A",
        "is_correct": true
      }
    ]
  }
}
```

**错误情况处理**

| 错误 | 处理 |
|------|------|
| 有题目未作答 | 返回 code=1005，提示"还有题目未作答" |
| 报告已生成 | 直接从 reports 表读取返回，不重复调用 AI |
| AI 超时/失败 | 返回 code=1006，提示"报告生成失败，请重试"，不写 reports 表 |

### 功能 5：用户可查看历史答题记录

**Phase 5 方案（无用户系统，本地存储）**

```
前端本地存储（wx.setStorageSync）
  key: 'quiz_history'
  value: JSON 数组，每条记录：
    { session_id, topic, accuracy_rate, correct_count, total_questions, created_at }
```

存储时机：报告页收到 report 接口响应后，前端读取本地历史 → push 新记录 → 写回。

历史页面（`/pages/history/history`）：
- 读取 `wx.getStorageSync('quiz_history')`
- 按 `created_at` 倒序展示
- 每条记录显示：主题 + 正确率 + 答题时间
- 最多展示最近 20 条（超出则截断）

**Phase 6 切换方案（用户系统上线后）**

- 增加 `GET /api/quiz/history` 接口（需 JWT）
- 历史页判断是否已登录：已登录 → 调接口，未登录 → 读本地存储
- 本地历史在首次登录时可选择同步到服务端（可选，非 MVP 必须）

## 三、数据库表设计

### 3.1 quiz_sessions（闯关会话表）

```sql
CREATE TABLE quiz_sessions (
    id           BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    topic        VARCHAR(255) NOT NULL                            COMMENT '学习主题',
    status       VARCHAR(20)  NOT NULL DEFAULT 'in_progress'      COMMENT 'in_progress/completed',
    total_questions INT        NOT NULL DEFAULT 5                  COMMENT '题目总数',
    correct_count   INT        NOT NULL DEFAULT 0                  COMMENT '答对题数',
    created_at   DATETIME     NOT NULL DEFAULT NOW()              COMMENT '创建时间',
    updated_at   DATETIME     NOT NULL DEFAULT NOW()
                              ON UPDATE NOW()                     COMMENT '更新时间',
    user_id      BIGINT       NULL                                COMMENT 'Phase 6 新增，FK→users.id',
    INDEX idx_user_created (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='闯关会话';
```

### 3.2 questions（题目表）

```sql
CREATE TABLE questions (
    id             BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    session_id     BIGINT       NOT NULL                            COMMENT 'FK→quiz_sessions.id',
    question_no    INT          NOT NULL                            COMMENT '题号 1-5',
    question_type  VARCHAR(20)  NOT NULL                            COMMENT 'single/multiple/judge',
    content        TEXT         NOT NULL                            COMMENT '题干',
    options        JSON         NOT NULL                            COMMENT '选项数组',
    correct_answer VARCHAR(255) NOT NULL                            COMMENT '正确答案',
    explanation    TEXT         NOT NULL                            COMMENT 'AI 讲解',
    knowledge_tags JSON         NULL                                COMMENT '知识点标签数组',
    difficulty     VARCHAR(10)  NOT NULL DEFAULT 'medium'           COMMENT 'easy/medium/hard',
    user_answer    VARCHAR(255) NULL                                COMMENT '用户作答',
    is_correct     TINYINT(1)   NULL                                COMMENT '是否答对 1/0',
    created_at     DATETIME     NOT NULL DEFAULT NOW()              COMMENT '创建时间',
    UNIQUE INDEX idx_session_no (session_id, question_no),
    CONSTRAINT fk_q_session FOREIGN KEY (session_id)
        REFERENCES quiz_sessions(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='题目';
```

### 3.3 reports（报告表）

```sql
CREATE TABLE reports (
    id            BIGINT        NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    session_id    BIGINT        NOT NULL UNIQUE                     COMMENT 'FK→quiz_sessions.id（1:1）',
    accuracy_rate DECIMAL(5,2)  NOT NULL                            COMMENT '正确率 0-100',
    summary       TEXT          NOT NULL                            COMMENT 'AI 知识总结',
    weak_points   JSON          NOT NULL                            COMMENT '薄弱知识点数组',
    evaluation    VARCHAR(100)  NOT NULL                            COMMENT '评价话术',
    created_at    DATETIME      NOT NULL DEFAULT NOW()              COMMENT '创建时间',
    CONSTRAINT fk_r_session FOREIGN KEY (session_id)
        REFERENCES quiz_sessions(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='答题报告';
```

### 3.4 users（用户表，Phase 6 新增）

```sql
CREATE TABLE users (
    id          BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    open_id     VARCHAR(64)  NOT NULL UNIQUE                     COMMENT '微信 open_id',
    nickname    VARCHAR(64)  NULL                                COMMENT '昵称',
    avatar_url  VARCHAR(512) NULL                                COMMENT '头像 URL',
    created_at  DATETIME     NOT NULL DEFAULT NOW()              COMMENT '注册时间',
    updated_at  DATETIME     NOT NULL DEFAULT NOW()
                             ON UPDATE NOW()                     COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户';
```

**表关系**

```
users (Phase 6)
  └─< quiz_sessions (1:N)
          ├─< questions (1:5)
          └── reports (1:1)
```

## 四、API 接口文档

### 统一规范

**请求头**：`Content-Type: application/json`（Phase 6 写接口增加 `Authorization: Bearer <JWT>`）

**统一响应格式**：
```json
{
  "code": 0,         // 0=成功，非0=业务错误
  "message": "ok",   // 错误时为中文描述
  "data": {}         // 业务数据，错误时为 null
}
```

**业务错误码**

| code | 含义 |
|------|------|
| 1001 | 会话不存在 |
| 1002 | 该题已作答 |
| 1003 | 题号无效 |
| 1004 | 答案格式不正确 |
| 1005 | 有题目未作答，无法生成报告 |
| 1006 | AI 服务异常，请重试 |
| 1007 | 参数校验失败 |
| 2001 | 用户不存在（Phase 6） |
| 2002 | Token 无效或已过期（Phase 6） |

## 五、前端路由规划

### 页面清单

| 路径 | 页面名 | tabBar | 进入方式 | 功能说明 |
|------|--------|--------|----------|---------|
| `/pages/index/index` | 首页 | ✅ | switchTab | 输入主题 → 触发生成 → 跳闯关页 |
| `/pages/quiz/quiz` | 闯关答题页 | ❌ | navigateTo | 渲染 5 题，逐题提交 |
| `/pages/report/report` | 结果报告页 | ❌ | navigateTo | 展示报告，"再来一关"→ switchTab 首页 |
| `/pages/history/history` | 历史记录页 | ✅ | switchTab | Phase 5 本地存储，Phase 6 服务端 |
| `/pages/profile/profile` | 个人中心页 | ✅（Phase 6） | switchTab | Phase 6 新增，微信头像/昵称/历史统计 |

### 导航约束（来自已知 Bug 修复记录）

```
⚠️ tabBar 页不能用 Taro.navigateTo / Taro.redirectTo 跳转
✅ 跳 tabBar 页（首页/历史/个人中心）：Taro.switchTab({ url: '/pages/xxx/xxx' })
✅ 跳非 tabBar 页（闯关/报告）：Taro.navigateTo({ url: '/pages/xxx/xxx?session_id=1' })
✅ 报告页完成后回首页：Taro.switchTab({ url: '/pages/index/index' })
```

### 页面间数据传递

| 路径 | 传递方式 | 传递内容 |
|------|----------|---------|
| 首页 → 闯关页 | URL 参数 | `session_id=1`（后端返回） |
| 首页 → 闯关页 | Zustand store | `questions[]`（5 题数据，含 options） |
| 闯关页 → 报告页 | URL 参数 | `session_id=1` |
| 报告页 | 调接口 | 用 `session_id` 调 `POST /api/quiz/report` |

> 题目数据不放 URL 参数（太长），用 Zustand 全局 store 临时存储。

## 七、风险与已知约束

| 风险 | 解决方案 |
|------|----------|
| DeepSeek 不支持 `response_format` | 全程用 `llm.with_structured_output(Pydantic Model)` |
| `Taro.redirectTo` 无法跳 tabBar 页 | 跳 tabBar 一律用 `Taro.switchTab` |
| DeepSeek 响应慢（3-8 秒） | 前端全程 loading 状态，后端超时 60 秒 |
| DeepSeek JSON 结构偶发不合规 | Pydantic 校验失败时返回 1006，前端提示重试 |
| Phase 5 无用户系统 | 历史记录用 `wx.setStorageSync`，session 无 user_id |
| Phase 6 只扩展功能 | **禁止修改** Phase 5 出题/答题/报告核心逻辑 |
| `quiz_sessions.user_id` Phase 5 为 NULL | 加 Alembic 迁移脚本：Phase 6 再加 FK 约束 |
| 多选题答案顺序不定 | 判定时对双方 `set()` 比较，不依赖顺序 |
| 题目数据传闯关页方案 | 用 Zustand 存储，不放 URL 参数 |
